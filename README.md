# CS-255 DriverPass System Analysis and Design

## Project Overview

DriverPass was a project for a client who wanted a system to help students prepare for their driving tests. The system needed to allow customers to create accounts, take online practice tests, schedule driving lessons, and manage appointments. Employees also needed access to manage schedules, vehicles, instructors, and customer information.

## What I Did Well

I think I did a good job identifying the main requirements and organizing them into the Business Requirements Document. I also learned how to use UML diagrams to show how different parts of the system interact. The activity and sequence diagrams helped me understand the steps involved in scheduling a driving lesson.

## What I Would Improve

If I could revise one part of my work, I would improve the activity diagram for creating customer accounts. I would make the error-handling process clearer so that if a customer or employee enters incorrect information, they can return to the necessary fields and correct it without restarting the entire process.

## Understanding User Needs

I used the client's requirements to identify what customers, instructors, and employees needed from the system. I considered their different responsibilities when creating the use case diagrams and designing the system. Understanding user needs is important because a system should not only work technically but also be practical and easy for people to use.

## My Approach to Software Design

I start by reviewing the requirements and identifying the users and their responsibilities. Then I organize the main functions and use diagrams to visualize how the system should work. In future projects, I want to continue using UML diagrams, clear documentation, and feedback to identify problems early and improve my designs.
